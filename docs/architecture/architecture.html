Repository Intelligence Engine — architecture

Drawn from the source of repo-intelligence-engine at commit 8025afa, which merges PR #2 (nest-resolution-and-taskgen-fixes). Read on 2026-09-28. Every box is labelled with the file that implements it. Companion page: sequence of one assisted benchmark run.

Two design decisions

1Edges are file-level, not symbol-level

An import statement belongs to a file, not to a symbol. So edges stores from_file → to_file, with to_file already resolved to an absolute path at index time. to_symbol_id is filled in only for named imports. Default, namespace and side-effect imports, and export *, get a single edge with NULL there. Star re-exports are tagged reexport_star.

This keeps every query a single table walk. dependency_path now takes a symbol name or a file path at either end. A file argument resolves straight to a node, which is how a symbol-less barrel like index.ts became nameable. It then runs a BFS over edges. find_circular_dependencies runs Tarjan over DISTINCT from_file, to_file, filtered to is_type_only = 0.

Where it lives: src/storage/schema.sql, src/indexer/index.ts (extractEdges), and src/engine/index.ts (dependencyPath, looksLikeFilePath, findCircularDependencies).

2MCP is an adapter, not the product

Each server.tool() handler in src/mcp-server/index.ts passes zod-validated arguments to the matching function in src/engine/index.ts and returns JSON.stringify of the result. The only extra work any handler does is presentational: reindex formats the engine's unresolved_internal_imports into a warning string using describeUnresolved.

Because the engine stands alone, the CLI, all 146 tests, oracle/compare.ts and the harness setup code call it directly. src/mcp-server/index.test.ts connects a real MCP client over InMemoryTransport and asserts toEqual between each MCP result and the direct engine call. In the benchmark, the only difference between the two arms is the --mcp-config flag.

Where it lives: src/mcp-server/index.ts, src/mcp-server/index.test.ts, and benchmarks/harness/claude.ts (claudeArgs).

What PR #2 changed in this picture

  • src/indexer/resolution.ts (new). It finds internal imports (relative, or matching a paths alias) that the compiler can't resolve, using the per-import ESM/CJS mode the compiler itself uses. indexRepository and reindex now return them instead of silently dropping the edges. On nest, 556 cross-package imports failed this way, because directory-style aliases never resolve in "type": "module" packages.
  • Callers act on the partial-index signal. indexer/cli.ts prints a warning, the MCP reindex tool adds a warning field, harness/cli.ts refuses to benchmark, and taskgen/generate.ts refuses to generate unless --allow-unresolved is passed.
  • dependency_path accepts file paths. An argument containing a slash or a source-file extension is treated as a file.
  • New task category, dependency_path. Tasks are generated from source edges in generate.ts using graph.ts's bfsDepths, and graded by validators.ts's validateImportPath, which accepts any valid chain or null for "no path". Change-impact tasks that hinge on a broken named re-export are now dropped.
  • Recorded results. benchmarks/results/harness/ now holds two graded runs, each next to the exact task set it used.
