One assisted benchmark run: sequence

This is the path through benchmarks/harness/ for a single task running on the rie arm, as written in the code at commit 8025afa (after the PR #2 merge). The example task is dependency_path, the category where the graded nest run showed the engine paying for itself. The purple segment is the only part the baseline arm never runs. Back to the architecture diagram.

What the code pins down

  • The index is built once, before any agent starts, and has to be complete. harness/cli.ts calls openDb and reindex on benchmarks/harness-<label>-index.db. If reindex returns any unresolved_internal_imports, the harness throws instead of running: a rie arm answering from a partial index would be measuring the tsconfig, not the tool. Each run's MCP server then opens that same file read-only in practice. The reindex tool exists, but the harness never calls it.
  • dependency_path takes files as well as symbols. An argument containing a slash or a source-file extension is resolved against the stored paths (exact match, then a unique suffix match, case-insensitive). The BFS follows every edge, including type-only ones, because the question is about imports, not runtime.
  • Both arms get the same command except for one flag. claudeArgs in claude.ts gives every run --tools Read,Grep,Glob --setting-sources project,local --strict-mcp-config --permission-mode bypassPermissions, and adds --mcp-config only for the rie arm.
  • Metrics come from the transcript, not from the CLI's own report. findTranscript looks up ~/.claude/projects/*/<session-id>.jsonl using a session id the harness chose itself. parseTranscript counts tool_use blocks and adds up input, output, and cache token usage from main-thread assistant turns, skipping sidechains.
  • Grading needs neither the engine nor the repo. gradeAnswer reads only the last fenced JSON block and checks it against task.expected, which taskgen built earlier from the emitted-JS oracle. For a path task, validateImportPath accepts any chain whose every hop is in path_edges, or null when no path exists. A reply with no parseable block is graded wrong, and a crashed run counts as wrong rather than missing.
  • The older run.ts harness follows the same path up to the grading step. It sends the hand-written prompt as is, then sets located_oracle by checking whether the answer text contains the oracle filename. It is a presence check, not a grader.
